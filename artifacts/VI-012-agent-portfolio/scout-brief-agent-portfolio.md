# Small models make the harness decisive

As of November 2026, the evidence says that for a 7B to 27B open-weight model the harness around it decides more of an agent's quality, cost and reliability than the model does, and that is the fact a VI agent portfolio should be organised around. A July 2026 source-code study of eleven production coding harnesses found the agent loop itself can be written in roughly **100 lines** while the surrounding control code runs to **about 1.1 million lines** in the largest case, and that none of the eleven imports a general-purpose agent framework ([Barbaste et al.](https://arxiv.org/pdf/2609.00006)). A controlled factorial on SWE-bench Verified measured **harness variance at 7.8 times model variance** and reversed six of nine model rankings when the harness changed ([Zhang et al.](https://arxiv.org/pdf/2605.23950.pdf)); a harness evolved on one model transferred **+10.1 points to DeepSeek-v4-flash** with no re-tuning ([Lin et al.](https://arxiv.org/html/2604.25850v2)); and the most common failure for self-hosted models is a tool-call parser or chat-template mismatch that is "easily confused with a lack of capability" ([OpsBench, NeurIPS 2026](https://neurips.cc/virtual/2026/160089)). Industry and academia classify agents on three independent axes, control-flow shape, autonomy tier by human role, and task class, and separate a single-call task head from a workflow from an agent by one test: whether the model's output changes which code runs next, and whether the model or the code decides the next step and when to stop. Cost-controlled comparisons from 2024 to 2026 put structured, cheap builds (one call plus retry, a static workflow, a function-calling single agent, a domain-tuned small model) on the accuracy-cost frontier for bounded tasks, while autonomous and multi-agent builds win only on breadth-first, tool-mandatory or unpredictable-step tasks at **2 to 15 times the tokens**. The standard way to compare several builds of one purpose is a convex accuracy-cost Pareto frontier, pass^k reliability rather than pass@k, at least three seeds with paired statistics, judges calibrated against expert labels, and the harness version pinned into the variant's identity. Vendor libraries publish cards (name, purpose, category, publisher, version, deploy path) and keep owner, model, policy and evaluation in a separate governance layer; the adoptable VI entry merges both onto an A2A Agent Card core. SR 26-2 (17 April 2026) places generative and agentic AI outside model-risk scope, so the agent register must carry its own tiers, owners and controls. What the Head of VI should borrow: own the loop and standardise the edges (MCP for tools, OpenTelemetry for traces, A2A for agent cards); register every candidate on the three axes with task head or workflow as the default; ship each purpose as three pinned variants; compare them on the planned evaluation harness with the judge-model family; and publish each variant as one library entry a business team can start from.

## A hundred-line loop inside a million lines of control, placed between three gateways

Every reference architecture published between December 2024 and October 2026 converges on the same skeleton: an iterative action-observation loop around a model, typed tools, a context manager, a session and state substrate, a permission and guardrail layer, hooks or middleware for interception, and tracing. The eleven-harness study (Claude Code, Codex CLI, Gemini CLI, Mistral Vibe, OpenHands, Aider, Mini-SWE-Agent, Hermes, Pi, OpenCode, OpenClaw; about 4 million lines of code) names **seven subsystems**, each with a minimal and a maximal form: agent loop, LLM integration, tools and actions, memory and context, safety and permissions, orchestration, and extensibility, with the interface layer and the session substrate cutting across them ([Barbaste et al.](https://arxiv.org/pdf/2609.00006)). A June 2026 survey reaches a compatible six-component list (observation interface, context manager, control loop, action interface, state and artifact store, verification and governance) and defines the harness as the runtime that "decides what the model observes, how context is built, how actions run, how state persists, and how failures are caught and recovered" ([Guo et al.](https://arxiv.org/pdf/2606.20683)). For the business reader the implication is that an agent is a software product with a model inside it, not a model with a prompt, and the parts that make it safe, cheap and recoverable are the parts VI writes once and reuses.

The design rule that recurs in every vendor's guidance is that **the model proposes and the harness enforces**. Anthropic's own operator documentation splits every concern into a non-deterministic form ("Claude decides": prompts, instruction files, skills) and a deterministic form ("the harness has to execute this": hooks, deny rules, managed settings), and advises that "if you keep adding emphasis to a CLAUDE.md line and Claude still misses it, that's a sign the line belongs in a hook" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). OpenAI's guide layers relevance and safety classifiers, PII filters, tool safeguards rated low, medium or high risk, rules-based blocklists and human intervention for irreversible actions such as refunds and payments ([OpenAI](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)); AWS AgentCore evaluates Cedar policies at the tool gateway "before allowing tool access," outside the agent's code (vendor documentation, [AgentCore Policy](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy.html)); and a bank-grade design write-up states the principle as "the model can reason, but the harness must control," with five action classes from read-only to prohibited, secrets injected at call time so the model never sees credentials, and every run emitting a structured event to a SIEM ([Anderson, practitioner account with a fictional bank](https://dev.to/mike_anderson_d01f52129fb/securing-ai-agents-in-a-bank-from-daily-chatgpt-use-to-a-production-ready-secure-harness-1b99)). The eleven-harness study supplies the reason this rule is not optional: one harness's tool description "claims a read-before-edit check that the source does not implement," which the authors summarise as prompt text being "a behavioral wish, not a guarantee" ([Barbaste et al.](https://arxiv.org/pdf/2609.00006)).

The one component with consistently positive measured effect is verification. Adding a high-level verification step to a multi-agent coding system raised correctness **+15.6 points absolute** ([MAST, Cemri et al.](https://arxiv.org/html/2503.13657v2)); in 1,634 benchmark transcripts, explicit verification made success **13 to 87 percent more likely** and recovering from a mid-run error made it 1.5 to 4 times more likely ([HAL, Kapoor et al.](https://arxiv.org/pdf/2510.11977)); and in the harness-evolution study the gain from closing the verification and recovery loop (per-step self-checking, anomaly detection, checkpoint rollback) was the second of two main sources of improvement ([Zhang et al.](https://arxiv.org/pdf/2605.23950.pdf)). The only component with a measured negative effect was the system prompt itself: in a single-component ablation from a bash-only seed, long-term memory added +5.6 points, tools +3.3 and middleware +2.2, while the system prompt alone subtracted 2.3 ([Lin et al.](https://arxiv.org/html/2604.25850v2)). Harness gains come from tools, verification, recovery and memory, not from prompt length.

Managed harnesses appeared across 2026 as a product category: Claude Managed Agents (a "pre-built, configurable agent harness" with sessions, environments and vaults, beta header dated 2026-04-01; vendor claim, [Anthropic](https://platform.claude.com/docs/en/managed-agents/overview)), AgentCore Harness ("a managed agent loop invoked with a single API call," each session in a microVM; vendor claim, [AWS](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html)), Microsoft's Harness Agent ([Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/overview/agent-framework-overview)) and Cloudflare's Pi harness on Durable Objects ([Cloudflare](https://developers.cloudflare.com/agents)). They are useful as reference designs, but all assume frontier model APIs; a team serving its own models behind its own gateway will still build or adapt its own loop. That is also what the production evidence recommends: the 12-factor guidance to "own your control flow" ([HumanLayer](https://github.com/humanlayer/12-factor-agents)), Shopify's move from free-roaming agents that "just didn't work very well" over a large codebase to structured workflows with deterministic steps ([Shopify Engineering](https://shopify.engineering/introducing-roast)), and the eleven-harness finding that no production runtime imports LangChain or AutoGen.

### Engineering: the control plane, the ledger and the cache are the three things to build first

Three harness subsystems need deliberate design on VI's stack because their failure modes are structural rather than cosmetic. The first is the permission control plane. The Claude Agent SDK evaluates permission in a fixed order (hooks, then deny rules, then ask rules, then permission mode, then allow rules, then a callback), a hook deny always wins, and "auto-approved tools never reach canUseTool," so universal checks belong in a pre-tool hook ([Agent SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions)). Anthropic's auto mode (25 March 2026) is instructive as a reference for a classifier gate: a transcript classifier reviews each action in two stages, sees only user messages and tool calls (assistant text and tool outputs are stripped, "reasoning-blind by design"), applies more than 20 default block rules in four groups (destroy or exfiltrate, degrade security posture, cross trust boundaries, bypass review), tiers tools into allowlisted read-only, in-project writes and everything else, and stops the run after 3 consecutive or 20 total denials ([Anthropic](https://www.anthropic.com/engineering/claude-code-auto-mode)). The same documentation is explicit that a classifier is "a substitute for a human approver" and that "your 'never' rules belong in deny rules or hooks" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)), which fixes the layering for VI: hooks and deny rules for universal checks, a Cedar-style policy engine at the tool gateway for organisation-wide tool authorisation and audit, OS sandboxes for anything that executes code (both filesystem and network isolation are needed, because either alone leaves an exfiltration path; Anthropic's "84 percent fewer permission prompts" figure is an internal number with no published methodology, [Anthropic](https://www.anthropic.com/engineering/claude-code-sandboxing)), and a classifier only as prompt-reduction above those layers.

The second is the approval and session ledger. Every durable-execution design fetched (LangGraph checkpointers, Microsoft Agent Framework supersteps, Google ADK invocation resume, Cloudflare Workflows, Temporal) resumes by replaying from a boundary, and every one pushes idempotency onto tool authors: ADK states "tools run 'at least once' and may run more than once" ([ADK resume](https://adk.dev/runtime/resume/)), OpenAI's human-in-the-loop docs warn that "approval does not guarantee exactly-once execution," that deserialisation "does not authenticate the snapshot or the reviewer," and that approvals must be consumed atomically to prevent replay ([OpenAI Agents SDK](https://openai.github.io/openai-agents-python/human_in_the_loop/)), and Microsoft says to "treat checkpoint storage as trusted, private infrastructure" ([Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints)). The pause point that matters most is between the model choosing a tool and the tool running, which 12-factor identifies as "a common failure point" for orchestrators that cannot stop there ([Factor 6](https://github.com/humanlayer/12-factor-agents/blob/main/content/factor-06-launch-pause-resume.md)). For a regulated firm the consequence is that the approval record (who approved, what, when, under which authorisation) is a security object that belongs in the harness's own audit table, not in the model transcript, and every side-effecting tool needs an idempotency key and a reconciliation path.

The third is the context and cache discipline, which is where a self-hosted serving stack turns into cost and latency. Manus, after rebuilding its framework four times, calls KV-cache hit rate "the single most important metric" for a production agent, cites a 100:1 input-to-output token ratio and a tenfold price gap between cached and uncached input, and gives the recipe that maps directly onto vLLM: keep the prompt prefix stable (no timestamps), make context append-only with deterministic serialisation, enable prefix caching, and "use session IDs to route requests consistently across workers" (vendor practitioner account, [Manus](https://manus.im/en/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). vLLM's automatic prefix caching reduces prefill only and gives no benefit without a shared prefix ([vLLM](https://docs.vllm.ai/en/stable/features/automatic_prefix_caching/)); llm-d's endpoint picker scores replicas by KV-cache affinity ([llm-d](https://llm-d.ai/docs/architecture)). Context rot is real at every model size (performance "grows increasingly unreliable as input length grows" across 18 models, and Qwen3-8B began emitting random words around 5,000 words in a repetition task, [Chroma](https://www.trychroma.com/research/context-rot)), so the harness compacts for recall first, externalises state to files and notes, keeps failed actions and stack traces visible (Manus: "error recovery is a key indicator of agentic behavior"), and uses sub-agents as context firewalls that return 1,000 to 2,000-token summaries ([Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). The cost anti-pattern is the resent preamble: Claude Code resends about 16,581 tokens per turn against 829 for mini-SWE-agent (secondary report of a Shandong University study, [aiweekly](https://aiweekly.co/alerts/shandong-study-fancier-coding-harnesses-triple-cost-not-accuracy)), and the HarnessTax study found up to about 5x cost for the same model across harnesses with only ±2 to ±5 points of accuracy difference (secondary report, [Digital Applied](https://www.digitalapplied.com/blog/coding-agent-harness-cost-harnesstax-same-model-5x)).

### Engineering: where each component sits relative to Envoy, vLLM and sessions

The 2026 consensus splits agent traffic into three governed paths, and the harness sits between the first and the other two. The LLM gateway (Agent Router, formerly Envoy AI Gateway, now an Agentic AI Foundation project with Envoy as the data plane) routes and fails over model calls, keeps provider credentials out of workloads and enforces usage limits, and its documentation says plainly that it "does not tell an agent how to reason" ([Agent Router](https://theagentrouter.ai/docs/)). A vendor framing of the same split names an agent gateway for client-to-agent calls, an LLM gateway for agent-to-model calls and an MCP gateway for agent-to-tool calls with deny-by-default allow-lists and per-call logs (vendor article, [Maxim](https://www.getmaxim.ai/articles/agent-gateway-vs-llm-gateway/)). No primary source describes an end-to-end deployment combining Envoy-based routing, KV-cache-aware vLLM scheduling and an agent harness; the placement below is synthesised from component documentation.

| Layer | What it owns on VI's stack | Reference |
|---|---|---|
| Agent gateway (client to agent) | Who may invoke which registered agent; agent cards; credential stripping or forwarding | [A2A v1.0](https://a2a-protocol.org/latest/specification/); [Maxim (vendor)](https://www.getmaxim.ai/articles/agent-gateway-vs-llm-gateway/) |
| Harness library (application tier) | The loop; context manager and compaction; hooks and approval gates; session and approval ledger; step and budget caps; OTel spans with the session ID | [Barbaste et al.](https://arxiv.org/pdf/2609.00006); [12-factor](https://github.com/humanlayer/12-factor-agents) |
| LLM gateway (Envoy / Agent Router) | Model routing and failover, credential injection, token budgets per consumer, model-level telemetry | [Agent Router](https://theagentrouter.ai/docs/) |
| Tool / MCP gateway | Tool discovery, deny-by-default allow-lists, per-call Cedar-style policy on principal, tool, inputs and session history, per-call audit | [AgentCore Policy (vendor)](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy.html); [MCP spec](https://modelcontextprotocol.io/specification/2025-06-18) |
| Serving (vLLM behind a KV-cache-aware router) | Tool-call parser, chat template, reasoning parser and strict decoding per model family; prefix caching; session-ID affinity | [vLLM tool calling](https://docs.vllm.ai/en/stable/features/tool_calling/); [llm-d](https://llm-d.ai/docs/architecture) |
| Observability backend (Langfuse / OTel) | Traces nested in sessions; evaluation events attached to spans; post-hoc, not real-time gating | [Langfuse](https://langfuse.com/docs/observability/data-model); [OTel GenAI v1.37](https://github.com/open-telemetry/semantic-conventions/blob/v1.37.0/docs/gen-ai/gen-ai-spans.md) |

Two placement details carry risk. Tool-call encoding is configured at the vLLM endpoint (per-family parsers such as hermes, mistral, llama3_json, qwen3_xml, plus strict levels, where "named" tool choice "only guarantees a parsable call, not a high-quality one," [vLLM](https://docs.vllm.ai/en/stable/features/tool_calling/)) while schema design and retry or repair live in the harness, so the serving team and the harness team need a shared conformance suite per fine-tuned model before any capability conclusion is drawn. And OpenTelemetry's GenAI semantic conventions (inference spans, `execute_tool`, `invoke_agent`, `invoke_workflow`, token and duration metrics, a `gen_ai.evaluation.result` event since v1.38) remained in Development status with no stable release as of August 2026 and moved to a dedicated repository in v1.42 ([Greptime](https://greptime.com/blogs/2026-05-09-opentelemetry-genai-semantic-conventions); [TrueFoundry](https://www.truefoundry.com/blog/opentelemetry-genai-semantic-conventions)), so the harness should pin the semconv version and keep message content in external storage with a reference, the capture mode the spec recommends for sensitive data. A vendor-adjacent comparison of twelve observability platforms found that "none of the twelve returns a real-time, per-turn verdict on whether an agent turn was acceptable" ([Morph](https://www.morphllm.com/ai-agent-observability-tools)), which means real-time gating is the harness's job, not the tracer's.

## Three axes classify every candidate, and one test sorts task head from workflow from agent

There is no single accepted taxonomy of agents; four families coexist and are mixed in practice. Vendors publish control-flow taxonomies (Anthropic's workflow patterns, OpenAI's manager versus handoff, Google's five levels of agentic systems, Microsoft's agents-versus-workflows), governance bodies and some academics publish autonomy ladders graded by the human's role (Gartner, Feng et al., the Cloud Security Alliance, Microsoft's retrieval/task/autonomous tiers), academia publishes cognitive-architecture taxonomies (CoALA's memory, action and decision modules), and practitioners use an informal task-class vocabulary (copilot, deep research, coding, computer-use, ambient, judge, router). A September 2026 compendium concludes that "agent" and "agentic AI" are conflated and that agenticness should be measured as a set of capabilities along five dimensions rather than declared as a label ([Lassiter and Bent](https://arxiv.org/pdf/2609.11018)); Feng et al. argue separately that autonomy is a design decision independent of capability ([Feng, McDonald and Zhang](https://arxiv.org/abs/2506.12469)). Reading the schemes together, three axes recur and are independent of each other, so a VI register entry needs all three.

| Axis | Values | Source schemes |
|---|---|---|
| Control-flow shape | Single call (task head); prompt chain; router; parallel sectioning or voting; orchestrator-workers; evaluator-optimizer; open loop (agent); code agent | [Anthropic, Dec 2024](https://www.anthropic.com/research/building-effective-agents); [Google, Nov 2025](https://www.rivista.ai/wp-content/uploads/2025/11/1762811267168.pdf); [smolagents](https://huggingface.co/docs/smolagents/conceptual_guides/intro_agents) |
| Autonomy tier (by human role) | Observe, Advise, Act with approval, Autonomous (Gartner); L1 Operator to L5 Observer (Feng); Levels 0 to 5 (CSA) | [Gartner via IT Pro, May 2026](https://www.itpro.com/technology/artificial-intelligence/one-size-fits-all-agent-governance-sets-enterprises-up-to-fail); [Feng et al.](https://arxiv.org/abs/2506.12469); [CSA v2.0, Mar 2026](https://labs.cloudsecurityalliance.org/research/agentic-ai-autonomy-levels-control-framework-v2-csa-styled/) |
| Task class | Conversational copilot; extraction or task head; background or ambient; deep research; coding; computer-use; judge or critic; router | [LangChain survey, Jun 2026](https://langchain.com/state-of-agent-engineering); [HAL benchmark families](https://arxiv.org/html/2510.11977v1); [LangChain ambient agents](https://www.langchain.com/blog/introducing-ambient-agents) |

The autonomy axis is the one business stakeholders and governance will read first. Gartner's four tiers each come with their own trust boundary: Observe is read-only with outputs visible only to the requester; Advise produces recommendations a human executes and adds accuracy testing and training against automation bias; Act with approval can write, send or configure with explicit per-action approval and carries an approval-fatigue warning; Autonomous acts within guardrails with humans reviewing exceptions, and requires continuous monitoring, rapid rollback, circuit breakers and clear ownership. Gartner predicts that governance failures will lead **four in ten organisations to demote or decommission autonomous agents within a year** ([IT Pro](https://www.itpro.com/technology/artificial-intelligence/one-size-fits-all-agent-governance-sets-enterprises-up-to-fail)). The CSA framework attaches control categories (authorisation, boundary, oversight, accountability, recovery, governance) to each of six levels and states that Level 5 full autonomy is "not recommended for current enterprise deployments" ([CSA](https://labs.cloudsecurityalliance.org/research/agentic-ai-autonomy-levels-control-framework-v2-csa-styled/)). Feng et al. propose "autonomy certificates" stored in agent metadata that state the maximum level an agent may run at, backed by an autonomy case and invalidated by specification or environment changes ([Feng et al.](https://arxiv.org/html/2506.12469v2)). The task-class axis matters because it predicts which build wins (next section) and because it tracks demand: in a 1,340-respondent survey fielded November 2025, the top primary use cases were customer service (26.5 percent), research and data analysis (24.4 percent) and internal workflow automation (18 percent), with internal productivity leading at organisations above 10,000 employees ([LangChain](https://langchain.com/state-of-agent-engineering)).

The test that separates a task head from a workflow from an agent is the same in every source: who controls the control flow. Hugging Face's agency spectrum puts it in code shape: a simple processor (`process_llm_output(llm_response)`) where "LLM output has no impact on program flow"; a router (`if llm_decision(): path_a() else: path_b()`); a tool call (`run_function(llm_chosen_tool, llm_chosen_args)`); a multi-step agent (`while llm_should_continue(): execute_next_step()`); and a code agent that writes and runs its own code, with the advice to "regularize towards not using any agentic behaviour" because a deterministic workflow gives "a 100% reliable system with no risk of error introduced by letting unpredictable LLMs meddle in your workflow" ([smolagents](https://huggingface.co/docs/smolagents/conceptual_guides/intro_agents)). OpenAI says apps that add an LLM "without using it to control workflow execution," such as sentiment classifiers and single-turn LLMs, are not agents ([OpenAI](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)); Anthropic defines workflows as "predefined code paths" and agents as systems where the LLM "dynamically direct[s] their own processes and tool use" ([Anthropic](https://www.anthropic.com/research/building-effective-agents)); Google ADK's workflow agents sequence sub-agents "without consulting an AI model" ([ADK](https://adk.dev/agents/workflow-agents/)); and Microsoft's rule of thumb is "if you can write a function to handle the task, do that instead of using an AI agent" ([Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/overview/)). For the register, the operational version is three questions asked in order. Does the model's output change which code runs next? If not, the candidate is a task head: a classifier, extractor, summariser or judge-as-scorer, one call with a structured output. If yes, is the set of possible paths and the maximum step count fixed in code? Then it is a workflow: a chain, a router with specialists, parallel sectioning or voting, or a generator followed by a fixed critic, with programmatic gates between steps. Only if the model chooses the next action, the tool and the stopping condition inside a loop with state is it an agent. A fourth question precedes all three: if conditional logic could replace the model step and produce the same result, the step does not need a model at all.

The claim that most enterprise "agents" are workflows rests on measured evidence, not opinion. Menlo Ventures found that **only 16 percent of enterprise deployments and 27 percent of startup deployments qualify as true agents**, with most built around "fixed-sequence or routing-based workflows wrapped around a single model call," in a market where 76 percent of use cases are bought rather than built ([Menlo Ventures, Dec 2025](https://menlovc.com/perspective/2025-the-state-of-generative-ai-in-the-enterprise/)). Gartner estimates "only about 130 of the thousands of agentic AI vendors are real," coined "agent washing," and projects more than 40 percent of agentic projects cancelled by end-2027 ([Gartner via SIA, Jun 2025](https://www.staffingindustry.com/news/global-daily-news/gartner-says-agent-washing-is-taking-place)). The academic version is Agentless, a three-phase pipeline that "does not let the LLM choose future actions" and reached 32.00 percent on SWE-bench Lite at $0.70 per issue, the best open-source result at the time ([Xia et al.](https://arxiv.org/abs/2407.01489)). For VI this is permission, not a constraint: the register should default every new candidate to task head or workflow and promote to agent only when the step count is genuinely unpredictable or real tool interaction is required. Routing is the lowest meaningful agency level in Anthropic's, Hugging Face's and Mitchell et al.'s schemes ([Mitchell et al.](https://arxiv.org/abs/2502.02649)) and is the natural first job for a small fine-tuned task head that classifies and dispatches, including routing easy requests to a cheaper model and hard ones to a stronger one, which Anthropic's routing example describes explicitly.

## The simplest build that does the job wins on cost and reliability; freedom pays only where steps are unpredictable or tools are mandatory

For a business team the outcome of two years of controlled comparisons is simple: the cheapest, most structured build that can complete a task is usually the most accurate and the most predictable one too, and extra autonomy buys accuracy only in specific, recognisable situations while multiplying cost. On HumanEval, a plain retry strategy on GPT-4 reached **93.2 percent at $2.45**, a cheap-to-expensive escalation chain 85.0 percent at $0.27, and the most elaborate tree-search agent 88.0 percent at **$134.50**, more than fifty times the cost for lower accuracy ([Kapoor et al.](https://arxiv.org/html/2407.01502v1)). Across 19 tasks on DeepSeek-V3.1, hand-built static workflows averaged 0.64 accuracy at $0.70 per hundred examples against a ReAct loop's 0.56 at $1.66, an overhead the authors call the "agentic tax," while tasks that need real external tools scored zero without them ([CMU](https://arxiv.org/pdf/2606.00189)). Across 21,730 rollouts on nine benchmarks, the most expensive model sat on the cost-accuracy frontier in **only 1 of 9 benchmarks**, Gemini 2.0 Flash sat on 7 of 9, and one web task showed a ninefold cost difference for two percentage points ([HAL](https://arxiv.org/pdf/2510.11977)). A 2025 wealth-management benchmark found low-autonomy prompts resolved 4 of 12 tasks against 2 of 12 for high-autonomy prompts, with failures dominated by authentication, delivery and wrong paths rather than reasoning ([Edinburgh MSc](https://arxiv.org/html/2512.02230v1)). For a regulated asset manager the HAL finding that failed agents violated a benchmark instruction in their final answer more than 60 percent of the time, and that some hard-coded "plausible" solutions to pass tests, is the reason the default variant is a workflow with model steps, with an autonomous variant allowed only behind deterministic validators and end-state checks.

The situations where more freedom pays are consistent across sources. Real tool interaction cannot be done by a single call, so a function-calling loop is mandatory for tasks like customer-service transactions or multi-system lookups ([CMU](https://arxiv.org/pdf/2606.00189); [τ-bench](https://arxiv.org/pdf/2406.12045)). External, verifiable feedback (unit tests, schema validators, environment state) makes an evaluate-and-retry loop pay, whereas asking the model to critique itself without such feedback lowers accuracy: GPT-4 fell from 95.5 to 89.0 on GSM8K over two rounds of intrinsic self-correction ([Huang et al.](https://arxiv.org/html/2310.01798v2)), and the original Reflexion authors found a small model (starchat-beta) showed no improvement at all and that Reflexion lost on MBPP because 16.3 percent of its self-generated tests were false positives ([Shinn et al.](https://arxiv.org/pdf/2303.11366)). Breadth-first, read-heavy research that exceeds one context window is where orchestrator-workers wins: Anthropic reports a lead agent with sub-agents beat a single agent by 90.2 percent on an internal research evaluation at about 15 times chat tokens, with token spend explaining about 80 percent of the variance and the pattern a poor fit for shared-context work "and most coding tasks" (vendor claim, [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)). The largest controlled study of multi-agent scaling, 260 matched-compute configurations across six benchmarks including Finance-Agent, found performance relative to a single agent ranging from **+80.8 percent on financial reasoning with a centralised coordinator to −70.0 percent on sequential planning with independent agents**, with error amplification of 17.2x for independent versus 4.4x for centralised designs and gains shrinking once single-agent accuracy exceeds about 45 percent; its conclusion is that "architecture-task alignment, not number of agents, determines collaborative success" ([Google Research, DeepMind and MIT](https://arxiv.org/html/2512.08296)). Cognition's April 2026 update narrows what works in practice to generator-verifier review loops where the verifier "sees only the diff," escalation to a stronger model, and manager-child map-reduce, while parallel-writer swarms still fail ([Cognition](https://cognition.com/blog/multi-agents-working)). Debate, the most intuitively appealing multi-agent pattern, is dominated by plain self-consistency at equal budget: no debate method exceeded a 20 percent win rate against chain-of-thought across 36 model-benchmark settings, and the only reliable lever was mixing heterogeneous models ([Stop Overvaluing Multi-Agent Debate](https://arxiv.org/pdf/2502.08788)).

The published comparisons therefore justify a standard variant set per purpose, which is what the portfolio should ship. Variant A is a task head or fixed workflow: cheapest, most predictable, wins on bounded tasks. Variant B is a single function-calling agent: wins where tools are required and the domain is narrow, but degrades as tool count grows (a single agent on τ-bench retail held with one distractor domain and "falls off sharply" with two or more, [LangChain](https://www.langchain.com/blog/benchmarking-multi-agent-architectures)). Variant C is orchestrator-workers or supervisor: wins on breadth-first research at 4 to 15 times the tokens and needs handoff hygiene. This is also the only vendor pattern that productises side-by-side choice: Databricks Agent Bricks runs an optimisation search and then asks the user to "select the iteration that matches your preferred balance of quality and cost" (vendor claim, [Databricks](https://www.databricks.com/company/newsroom/press-releases/databricks-launches-agent-bricks-new-approach-building-ai-agents)), and LangChain's Open Deep Research keeps its legacy "workflow" (plan-and-execute with human approval, "emphasizes accuracy") and "multi-agent" (parallel researchers, "optimized for speed") implementations alongside the current supervisor design and documents why parallel section-writing produced disjoint reports ([LangChain](https://www.langchain.com/blog/open-deep-research)).

### Engineering: what is specific to 7B to 27B open-weight models

Five things change when the model is a fine-tuned 7B to 27B open-weight model rather than a frontier API. First, the capability gap is real but a year wide: on BFCL v4 the best 9B to 35B open models score 66 to 69 percent (Qwen3.5-27B 68.5, Qwen3.5-9B 66.1) against 73 to 77 percent for frontier models (Claude Opus 4.5 77.47, Sonnet 4.5 73.24), with a long tail of 7B to 14B models at 25 to 45 percent (Qwen3-8B 42.57, Gemma-3-27b 29.47, Llama-3.1-8B 25.83) on an aggregator snapshot that mixes imported and self-reported rows ([BenchmarkList](https://benchmarklist.com/benchmarks/bfcl_v4/)). Fine-tuned small agents routinely match or beat the frontier model of 6 to 18 months earlier on narrow verifiable tasks (xLAM-2-8B 72.83 on BFCL v3 against GPT-4o's 69.58; WebRL took Llama-3.1-8B from 4.8 to 42.4 percent on WebArena-Lite against GPT-4o's 13.9, [WebRL](https://arxiv.org/html/2411.02337v3)) but trail the contemporaneous frontier by 15 to 40 points on broad agentic tasks (SWE-smith 32B at 40.2 versus its teacher's 58.2; BankerToolBench 32B at 0.14 after RL against frontier pass@1 of 16 percent, where bankers rated 0 percent of any model's deliverables "sendable as-is," [BankerToolBench](https://arxiv.org/pdf/2604.11304)). The regime where a trained small agent wins is narrow task, fixed tool surface, verifiable reward.

Second, format sensitivity dominates. Small and tool-tuned open models were the most sensitive in a 39-model, 26-variation study: JSON tool documentation beat XML, Python or JSON return formats beat XML, and Llama-3.1-8B dropped significantly once tags or XML were required ([BFCL prompt variation](https://gorilla.cs.berkeley.edu/blogs/17_bfcl_v4_prompt_variation.html)); undocumented choices of seed, multi-turn template, thinking history and system prompt moved Qwen3-4B's BFCL multi-turn score from 22.7 to 37.2 before any training ([Amazon, ICML 2026](https://arxiv.org/pdf/2606.00135)). The serving stack is part of the variant: Qwen's documentation says "protocol adherence is not guaranteed," recommends the hermes-style template and warns against stop-word templates with reasoning models ([Qwen](https://qwen.readthedocs.io/en/latest/framework/function_call.html)); a field test on a DGX Spark saw Gemma 4 26B-A4B produce more than 40 tool-calling errors in OpenHands and never finish a trivial task, yet fix the same bug in SWE-agent in nine steps, concluding "Gemma 4 can code. It just can't fill out JSON forms reliably" ([ai-muninn](https://ai-muninn.com/en/blog/swe-bench-local-models-framework-matters)); and a Qwen 3.5 27B/35B report traced tool calls emitted mid-reasoning and parser breakage on `<`, `>` and `&` to the chat template and parser choice ([Allan Chan](https://allanchan339.github.io/bug-fixes/2026/04/13/Qwen35-tool-calling.html)). Harnesses that work with open models carry explicit accommodations: Hermes repairs schema drift such as "42" to 42, and OpenCode swaps editing toolsets per model family ([Barbaste et al.](https://arxiv.org/pdf/2609.00006)).

Third, constrained decoding helps rather than hurts once reasoning precedes the grammar. Early results showed JSON-schema constraints collapsing LLaMA 3 8B on GSM8K from 75.13 to 48.90 ([Tam et al.](https://arxiv.org/html/2408.02442v3)), but JSONSchemaBench found a fast engine (Guidance at 6 to 9 ms per token against 15 to 17 unconstrained) improved downstream accuracy (GSM8K 80.1 to 83.8) and attributed earlier declines to prompting ([Geng et al.](https://arxiv.org/html/2501.10868v3)), and an 18-model study of 1.5B to 32B models showed the degradation comes from constraining too early: letting the model reason freely and applying the grammar after a trigger gave a 100 percent parse rate at +5 to 20 tokens and lifted LLaMA3-8B GSM8K from 66.2 natural to 77.9 and Qwen3-1.7B from 34.8 to 76.2 ([Thinking Before Constraining](https://arxiv.org/html/2601.07525)). vLLM's structured-output modes (xgrammar default, per-tool `strict`, `--tool-strict-level`) implement this at the endpoint ([vLLM](https://docs.vllm.ai/en/stable/features/tool_calling/)). The recipe is native function-calling format with JSON tool docs, grammar applied after a free reasoning segment, and schema validators as the first gate in both evaluation and any training reward, which is exactly how Shopify ordered its production reward (syntax and schema validators ahead of a semantic judge) after observing reward hacking such as hallucinated IDs and tag tricks (vendor account, [Shopify Engineering](https://shopify.engineering/building-production-ready-agentic-systems)).

Fourth, the cost-effective ordering of improvement methods is optimiser first, training later. GEPA lifted Qwen3-8B by +9.62 aggregate points across four tasks using 2,426 to 7,051 rollouts against GRPO's +3.68 with 24,000 rollouts ([GEPA](https://arxiv.org/pdf/2507.19457v2)); DSPy's documentation advises using a larger model as the reflection model when optimising smaller ones, since it is called only a handful of times (vendor docs, [DSPy](https://dspy.ai/current/getting-started/gepa-optimization/)); self-reported GEPA cases include gemma-3-12b malformed JSON falling from 40 percent to under 3 percent at Dropbox and customer-support judge agreement rising from 68.88 to 88.89 percent at Nubank ([GEPA use cases](https://gepa-ai.github.io/gepa/guides/use-cases/)); and alternating prompt optimisation with LoRA beat weights-only by up to 60 percent on 7B to 8B models ([BetterTogether](https://arxiv.org/html/2407.10930v2)). When training is warranted, verified synthetic trajectories plus SFT (xLAM-2) and GRPO on a few hundred to a few thousand verifiable tasks (ToolRL; Qwen2.5-7B from 55 to 78 percent on BFCL multi-turn with 100 training questions, vendor account, [Bespoke Labs](https://bespokelabs.ai/blog/improving-multi-turn-tool-use-with-reinforcement-learning)) are the evidence-backed routes, and RL gains hold across harnesses (Tmax-27B's +3.1 on Terminal-Bench 2.0 held at ≥9 points per harness on Terminal-Bench Lite, [Tmax](https://arxiv.org/pdf/2606.23321)).

Fifth, harness choices invert between small and large models. In a 176-setting study on Nemotron-3 30B/120B/550B, predefined tools helped the 30B model by +15.0 on SWE-bench and +10.1 on Terminal-Bench while bash-only was better and 30 to 53 percent cheaper for the 550B model; a planning tool helped the weakest model by +11.6 but cost stronger models accuracy; and context management mattered most under tight budgets (a 35.7-point gap at 32k context, 2.7 at 128k) ([Empirical harness study](https://arxiv.org/pdf/2609.20804)). Tmax found the keystroke-level Terminus-2 harness "more brittle with small models" than a simple persistent shell. Harness gains were larger on weaker models in Terminal-Bench compilations (Haiku 4.5 at 37.6 percent under Meta-Harness versus 35.5 under Goose, [Vaughan](https://codex.danielvaughan.com/2026/04/09/harness-performance-terminal-bench/)). Two reliability pathologies hit small models hardest: coherence collapse, where the agent reaches and edits the right code and then destroys it, accounted for 48.5 percent of edit-quality failures for Qwen3-32B against 31 to 33 percent for the GPT-5 family and grows with trajectory length, with intermediate checkpointing proposed as the fix ([AWS AI Labs](https://arxiv.org/pdf/2603.24631)); and naive episodic-memory scaffolds hurt long-horizon degradation for all ten open models tested, where task decomposition was the highest-leverage intervention ([Beyond pass@1](https://arxiv.org/html/2603.29231v1)). For VI's fleet: more structure, not more freedom; predefined typed tools; a planning or to-do tool; aggressive compaction; external validators in every loop because small models do not self-correct; and a local-remote decomposition where a small model handles chunked extraction and a stronger model aggregates, which recovered 97.9 percent of remote-only accuracy at 5.7 times lower cloud cost on FinanceBench and similar sets ([Minions](https://arxiv.org/html/2502.15964v1)).

## One purpose, several builds: compare on a Pareto frontier with pass^k, seeds, calibrated judges and a pinned harness

The business question the portfolio must answer for each purpose is "which build should a team start with," and the answer has to be defensible to the team, to risk and to the people paying for GPU hours. The 2024 to 2026 literature settled on a protocol with five parts. Report accuracy and dollar cost together and pick from the Pareto frontier, because accuracy alone is inflated by retries and the most expensive option is rarely on the frontier ([Kapoor et al.](https://arxiv.org/html/2407.01502v1); [HAL](https://arxiv.org/pdf/2510.11977)). Measure reliability as pass^k, the probability that all k independent trials succeed, because business processes need consistency: GPT-4o's function-calling agent scored about 61 percent pass^1 on τ-bench retail and **under 25 percent pass^8** ([τ-bench](https://arxiv.org/pdf/2406.12045)); gpt-4.1 fell from 0.74 to 0.53 pass^4 on retail and 0.34 to 0.19 on telecom in τ²-bench, where coordinating with an active user cost about 20 points and performance approached zero beyond about seven required actions ([τ²-bench](https://arxiv.org/pdf/2506.07982)); AgentArch's pass^k over eight trials peaked at about 6 percent where pass@1 reached 70 ([AgentArch](https://arxiv.org/html/2509.10769v2)); and OpsBench's best open model scored 80 percent in a single run and 50 percent pass^3 ([OpsBench](https://neurips.cc/virtual/2026/160089)). Anthropic's evaluation guide frames the same point as 0.75 cubed being about 42 percent and recommends starting with 20 to 50 tasks drawn from real failures ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). Run multiple seeds with paired per-item statistics, because single-run SWE-bench pass@1 varied 2.2 to 6.0 points across 60,000 trajectories even at temperature zero, identical systems showed apparent significance in up to 26 percent of comparisons, and meaning-preserving prompt changes produced a median 7.5-point spread ([Jarmak](https://arxiv.org/pdf/2608.13867)). Judge trajectories, not only final answers, with judges calibrated against human labels. And inspect logs for shortcuts and instruction violations, which HAL made a mandatory recommendation after finding agents locating gold answers online and hard-coding plausible solutions.

The judge-model family VI is planning is the right instrument if it is calibrated and kept away from its own backbone. Agent-as-a-Judge, which reads the artefacts and traces rather than the final text, aligned with human consensus at 88.5 to 90.4 percent against 60.4 to 84.2 for a plain LLM judge, at 2.29 percent of the human cost ([Zhuge et al.](https://arxiv.org/html/2410.10934v2)); Shopify's iterative judge prompting raised Cohen's κ against three or more product experts from **0.02 to 0.61 against a human ceiling of 0.69**, and the team rejects "rate this 0 to 10" judges in favour of an indistinguishability test (vendor account, [Shopify Engineering](https://shopify.engineering/building-production-ready-agentic-systems)); Databricks' answer-correctness judge reached 88.1 percent agreement (κ 0.64) with human majority and its judge-alignment tooling recommends at least 10 and preferably 50 to 100 labelled traces with at least 30 percent negative examples (vendor, [Databricks](https://www.databricks.com/en/blog/building-custom-llm-judges-ai-agent-accuracy)); and BankerToolBench's rubric judge reached κ 0.76 against human grades, above the humans' own 84.6 percent inter-rater agreement ([BankerToolBench](https://arxiv.org/pdf/2604.11304)). The survey of judge failure modes warns that judges favour outputs sharing their backbone and recommends either one base model for all roles or fully different models, escalation of low-confidence cases, and control of length and style bias ([When AIs Judge AIs](https://arxiv.org/pdf/2508.02994)), which argues for the judge family being drawn from a different model line than the agent variants it scores, or at least for cross-checking.

The harness is a first-class variable in every one of these comparisons, so a "methodology variant" must pin it. Same-model swings on Terminal-Bench 2.0 of 16 to 24 points by harness, against typical 2 to 3 points between model generations ([Vaughan](https://codex.danielvaughan.com/2026/04/09/harness-performance-terminal-bench/)), led the Tessl position paper to recommend that leaderboards require model, harness version, environment hash, dataset version and at least one non-model ablation ([Tessl](https://arxiv.org/pdf/2606.17799)), and the "Stop Comparing" authors proposed a seven-layer Harness Card (execution, tool, context, scheduling, observability, verification, governance) with trajectory metrics for recovery rate, context retention and control lag ([Zhang et al.](https://arxiv.org/pdf/2605.23950.pdf)). Enterprise tooling already implements the mechanics: LangSmith compares experiments against a baseline with per-feedback-key regressions and pairwise judging with randomised order ([LangSmith](https://docs.langchain.com/langsmith/compare-experiment-results)); Braintrust's `trialCount` reruns each input to measure variance and gates pull requests on regression ([Braintrust](https://docs.braintrust.dev/evaluate/advanced-evaluations)); TensorZero defines "variants" as different implementations of one function (prompt, model, hyperparameters, tool configuration) and selects among them online with a best-arm bandit it reports as 37 percent faster than uniform sampling in simulation (vendor claim, [TensorZero](https://www.tensorzero.com/blog/bandits-in-your-llm-gateway/)); and AgentOpt searches model-to-role assignments across nine models including Qwen3 32B and gpt-oss-20b at 62 to 76 percent lower evaluation cost than brute force ([AgentOpt](https://arxiv.org/html/2604.06296v2)). No published case reports which variant business users actually adopted when offered a choice, so VI's index, if it logs the choice alongside measured quality, cost, latency and reliability, would be a genuinely new dataset.

### Engineering: the minimum viable comparison protocol and the variant identity

The protocol the evidence supports, assembled for the planned evaluation harness, is a fixed task set per purpose with a held-out split (HAL found appropriate holdouts in only 1 of 8 domain-general benchmarks and the top WebArena agent hard-coding site-specific policies, [Kapoor et al.](https://arxiv.org/html/2407.01502v1)); at least three and preferably five to eight seeds per variant with paired per-item tests (McNemar for pass/fail, paired bootstrap otherwise) and a pilot of about 20 runs to size the study ([Jarmak](https://arxiv.org/pdf/2608.13867)); pass^1 and pass^k at the k matching the business's tolerance, mean and variance, cost per task and per success in actual gateway dollars plus token counts so costs can be recomputed, p50 and p95 latency, tool-call error rate and instruction-violation rate from log inspection; placement on a convex accuracy-cost frontier kept convex by randomising between variants; judges calibrated per criterion against at least three expert labellers with inter-rater reliability reported; and full traces archived with OTel evaluation events so scores travel with spans ([Greptime](https://greptime.com/blogs/2026-05-09-opentelemetry-genai-semantic-conventions)). Capability evaluations (start low, measure headroom) are kept separate from regression evaluations (hold near 100 percent), and the grader scores what the agent produced rather than the path it took, except where the policy is the point ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)).

A variant's identity is the tuple that must be held fixed for a result to mean anything: the VI model identifier with version and quantisation; the serving template, tool-call parser, reasoning parser and strict level at the vLLM endpoint; the harness library version; the tool set with MCP annotations; the prompt or optimised program version; the evaluation-set version; and the seeds. The reasons each field is there are concrete: quantisation on mixed GPUs caused drift past 30 to 40k tokens and a community checkpoint mixed XML and JSON tool formats after about 65k tokens ([Allan Chan](https://allanchan339.github.io/bug-fixes/2026/04/13/Qwen35-tool-calling.html)); OTel distinguishes `gen_ai.request.model` from `gen_ai.response.model` precisely because a request can be served by a dated variant ([OTel semconv v1.37](https://github.com/open-telemetry/semantic-conventions/blob/v1.37.0/docs/gen-ai/gen-ai-spans.md)); and Anthropic's own account of Managed Agents records that harness assumptions "go stale as models improve," with context resets that helped one model generation becoming "dead weight" for the next (vendor, [Anthropic](https://anthropic.com/engineering/managed-agents)). Program optimisation is itself a legitimate variant axis: the same purpose with a baseline prompt and with a GEPA-optimised prompt is a controlled comparison the team can run on its own harness with the judge family as the metric, and the optimisation cost is recovered after about 1,300 inferences in Kapoor et al.'s joint cost-accuracy runs.

## Vendor libraries ship cards; governance layers hold owner, model, policy and evaluation

Every major vendor now runs a catalogue with three layers, and the way they split what a business user sees from what governance records is the most useful borrowing for VI. The first layer is ready-to-run prebuilt agents scoped to a domain: ServiceNow announced "thousands of prebuilt AI agents" across IT, customer service and HR with a customer choice of supervised (human approval for every action) or fully autonomous mode (vendor claim, [TechTarget](https://www.techtarget.com/searchenterpriseai/news/366618614/ServiceNow-intros-AI-agent-studios-and-orchestrator)); Salesforce ships prebuilt Sales, Service and IT agents and claims "more than 12,000 implementations" (vendor claim, [Salesforce Developers](https://developer.salesforce.com/blogs/2025/10/build-and-optimize-agents-with-new-agentforce-360-features)); Anthropic released ten financial-services agent templates in May 2026 (pitch builder, earnings reviewer, general-ledger reconciler, KYC screener and others) with the statement that "users keep approval authority over Claude's output before anything reaches a client or is filed" (vendor claim, [InvestmentNews](https://www.investmentnews.com/fintech/anthropic-rolls-out-financial-services-agents-as-arms-race-with-openai-heats-up/266445)). The second layer is templates and blueprints as deployable code: Azure AI Foundry lists 21 solution templates each carrying a version number (most at v11 or v12) with no per-entry owner or evaluation field ([ai.azure.com](https://ai.azure.com/catalog/solutiontemplates)); Google's Agent Garden gives each entry pre-configured logic, GitHub source and a Deploy button with three deployment paths ([Google Cloud](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/agent-garden?hl=en)); NVIDIA's Deep Researcher blueprint exposes model profiles per role (a 30B model for intent classification and shallow research, a 550B model for deep research, a 31B model for summaries), which is a variant matrix inside one purpose (vendor documentation, [NVIDIA](https://build.nvidia.com/nvidia/aiq/blueprintcard)); AWS's agentcore-samples repository is organised as features, use cases, integrations, infrastructure-as-code and blueprints ([GitHub](https://github.com/awslabs/agentcore-samples)). The third layer is reusable components: Salesforce AgentExchange lists actions, prompt templates, topics ("groups of actions and instructions focused on one task, which keep agents within guardrails") and agent templates (vendor, [Salesforce](https://salesforce.com/news/press-releases/2025/03/04/agentexchange-announcement)); Microsoft's Copilot Agent Library separates Templates from Components and gives makers a browse-and-install role and administrators a publish role ([Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/kit-agent-library)). Business teams are designed to consume the first two layers through a maker role; engineering teams consume the last two.

What a public library entry contains is consistent and thin: name, one-line purpose, category or domain, publisher, version, deploy path and setup instructions. IBM's watsonx Orchestrate catalogue shows about 49 cards with logo, name, short description, category and publisher and no version, tool count or connector list ([IBM](https://www.ibm.com/products/watsonx-orchestrate/skills)). The fields a governed portfolio needs, owner, model, policy and evaluation, live in the vendors' governance layers instead: Microsoft's Graph `agentCardManifest` carries `ownerIds`, `managedBy`, `originatingStore`, `version` and `skills` ([Microsoft Graph](https://learn.microsoft.com/en-us/graph/api/resources/agentcardmanifest?view=graph-rest-beta)) and Agent 365 positions a Registry as the "single source of truth for all of an organization's agents" ([SD Times](https://www.sdtimes.com/net/microsoft-unveils-agent-365-a-unified-control-plane-for-agents/)); ServiceNow's AI Control Tower inventories agents, models and MCP servers as CMDB items with lineage and ownership and issues an "AI Passport," "a signed document that defines an agent's identity and permitted actions," enforced at runtime (vendor claim, [ServiceNow](https://www.servicenow.com/products/ai-control-tower.html)); Gemini Enterprise gives each agent a SPIFFE identity and a state machine of Private, Enabled, Suspended and Disabled with optional admin review before sharing ([Google Cloud](https://docs.cloud.google.com/gemini/enterprise/docs/agents-overview)); Databricks' Information Extraction agent publishes a quality report with overall quality, cost, throughput and per-field metrics (vendor, [Databricks](https://docs.databricks.com/aws/en/generative-ai/agent-bricks/key-info-extraction)). Realised value per agent is claimed only by Control Tower and is self-reported.

Financial-services firms disclose scale and oversight posture, not catalogue mechanics, and the de facto agent record visible in their disclosures is an identity, a named human owner, a line-of-business scope, logged actions with rationale, and an approval gate before any external effect. BNY runs "more than 130" digital employees in production with "logins, email addresses, and human managers," each "scoped, monitored, and fully auditable" with "every action logged, including the rationale," boundaries set per line of business, and more than one in three employees having built a custom agent on its Eliza platform (Forrester blog with promotional tone, [Forrester](https://www.forrester.com/blogs/bny-built-its-digital-workforce-backward-and-its-working/); [Evident](https://evidentinsights.com/bankingbrief/how-to-unchain-your-agent/)). Citi takes the opposite pole: its CTO insists agents need "technology controls, entitlements, identity, security, quality checks, and automated testing" and should not be treated as people, and its rollout of Devin to about 40,000 developers runs under the rule that "agents do not deploy code; they produce artifacts that developers review" ([American Banker](https://www.americanbanker.com/news/citi-is-rolling-out-agentic-ai-to-its-40-000-developers)). Goldman Sachs' CIO says of its agents "it never acts by itself" until error rates are close to zero; Capital One's Chat Concierge runs planner, validator and explainer agents on customised Llama with human-in-the-loop as "our first and most critical line of defense" ([American Banker](https://www.americanbanker.com/news/goldman-sachs-capital-one-prep-for-self-driving-ai-agents)). JPMorgan reports 250,000 employees on LLM Suite, about half daily, an eight-week release cadence and agents running "an hour or two" unattended, but no agent inventory or approval process ([CeFPro](https://connect.cefpro.com/article/view/inside-jpmorgan-llm-suite-as-ai-agents-spread-across-the-bank); [InvestmentNews](https://www.investmentnews.com/transformation/jpmorgans-new-ai-agents-can-work-for-hours-without-human-input/266944)). Across 50 tracked banks, nearly 10 percent of announced deployments are agentic, nearly three-quarters of those are internal, fewer than half are in full production, and "no clear framework yet exists for how risk changes as agents gain decision-making, access, and autonomy" ([Evident](https://evidentinsights.com/bankingbrief/how-to-unchain-your-agent/)). Vanguard's public record covers more than $500 million of measured value across five named non-agentic use cases with drift and bias monitoring, and no agentic disclosure as of November 2026 ([PYMNTS](https://www.pymnts.com/?p=3174670)). Forrester's recommendation, that each agent be "a governed identity with unique credentials, least privilege, full logging, and a named owner," with autonomy added in stages ([IT Pro](https://www.itpro.com/technology/artificial-intelligence/most-enterprises-are-still-unprepared-to-operationalize-it-it-leaders-are-bullish-on-agents-but-keeping-falling-at-the-final-hurdle-heres-why)), is the common denominator.

### Engineering: the adoptable library entry

The safest interoperable core for a VI entry is the A2A Agent Card v1.0 (name, description, supported interfaces, version, capabilities, default input and output modes, skills with id, name, description and tags, security schemes, signatures) served at `/.well-known/agent-card.json`, because it is what Google Cloud's Agent Registry validates and what Microsoft's Graph manifest mirrors ([Maxim write-up](https://www.getmaxim.ai/articles/a2a-agent-card.md); [Google Cloud](https://docs.cloud.google.com/agent-registry/json-schemas?hl=en)). A2A reached v1.0 with signed cards and 150-plus organisations in April 2026 but "no standard registry API exists yet" and the roadmap lists registry consolidation as planned ([Linux Foundation](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)), so the VI registry will be bespoke on top of cards. MCP's tool annotations (readOnlyHint, destructiveHint, idempotentHint, openWorldHint), validated by the same Google registry, give a ready vocabulary for per-tool risk tiers, and the MCP Registry's explicit private sub-registry design with a shared OpenAPI schema means VI can host its own tool catalogue with upstream compatibility ([MCP Registry preview](https://blog.modelcontextprotocol.io/posts/2025-09-08-mcp-registry-preview/)). The entry merges the public card with the governance record that vendors keep separate.

## SR 26-2 leaves agents outside model risk, so the register must carry its own tiers

The most consequential governance fact for a US financial firm is a footnote. SR 26-2, issued jointly by the Federal Reserve, OCC and FDIC on 17 April 2026 and superseding SR 11-7 and SR 21-8, states in footnote 3 that "generative AI and agentic AI models are novel and rapidly evolving. As such, they are not within the scope of this guidance," defines a model as "a complex quantitative method, system, or approach that applies statistical, economic, or financial theories" while excluding deterministic rule-based processes, and says a bank's own "risk management and governance practices should guide the determination of appropriate governance and controls" for tools outside scope ([Federal Reserve SR 26-2](https://www.federalreserve.gov/supervisionreg/srletters/SR2602.htm); [attachment](https://www.federalreserve.gov/supervisionreg/srletters/SR2602a1.pdf)). SR letters are addressed to supervised banking organisations; for an asset manager their weight is as the reference frame on which US financial-services model-risk programmes have been modelled and as the clearest statement of where supervisors stand. The effect is the same either way: neither the fine-tuned generative models underneath VI's agents nor the agents themselves can simply be filed under the existing model-risk inventory, and the firm's own framework has to say what governs them. Industry commentary (from a vendor with a commercial interest) proposes a five-pillar overlay: an inventory with owner, purpose, scope and review cadence; failure-specific monitoring for prompt injection and hallucination; source traceability; human-in-the-loop checkpoints and a kill switch; and change control with audit documentation ([CIMCON](https://cimcon.com/sr-26-2-regulates-your-models-not-your-ai-agents-what-banks-need-to-know/)), which matches the fields in the library entry above.

What this implies for the VI agent register is that it is a separate artefact from the model register, linked to it but with its own tiers and its own evidence. The autonomy tier is the organising field, because every governance scheme that has been published grades controls by it: Gartner's four tiers each define a trust boundary and a control set, the CSA matrix attaches six control categories to each level and requires executive authorisation, board oversight, a sub-minute kill switch and weekly autonomy reviews at Level 4 ([CSA](https://labs.cloudsecurityalliance.org/research/agentic-ai-autonomy-levels-control-framework-v2-csa-styled/)), and Feng et al.'s autonomy certificate makes the permitted maximum an explicit, revocable attribute of the agent ([Feng et al.](https://arxiv.org/html/2506.12469v2)). The register's evidence base is the evaluation record, not a validation report in the model-risk sense: pass^k at the business's tolerance, the judge's calibration against experts, the log-inspection findings, and the harness version that produced them, with a change to any component of the variant identity triggering re-evaluation. The controls are the harness controls already described, with the bank-harness design giving the practical shape: dedicated workload identities per system, secrets injected at call time, per-tool JSON policies, environment tiers from mock-only development to read-mostly production, a kill switch that disables write tools, connectors or users, and retrieved content treated as untrusted data with injection tests in CI ([Anderson](https://dev.to/mike_anderson_d01f52129fb/securing-ai-agents-in-a-bank-from-daily-chatgpt-use-to-a-production-ready-secure-harness-1b99)). The two poles of current practice, BNY's digital employee with a login and a manager and Citi's "not employees, entitlements and controls," are both accommodated by separating the agent identity record from the human accountability record, which the Graph manifest's `ownerIds` and `managedBy` fields already do. Publicly described financial-services agents remain in research and assist roles with human review; no fetched source describes an agent with direct transactional authority at an asset manager, and the register's default tier should reflect that.

## What the research could not close

The web-search budget was exhausted in all three research threads, and several gaps bear directly on the recommendations. No controlled study varies harness components specifically on 7B to 27B open-weight models; the transfer results in the harness-evolution paper are to mid-size API models and OpsBench does not name its models, so the "harness matters more for small models" conclusion rests on consistent indirect evidence rather than a direct factorial. No public case compares a 7B to 27B fine-tuned agent against the contemporaneous frontier model on quality, cost and latency in one table; Shopify, Databricks and DSPy figures each omit a dimension or compare against older frontier models. No published enterprise case, in financial services or elsewhere, offered business users several methodology variants of one agent and reported which they adopted, so the adoption half of VI's proposed index has no precedent to calibrate against. No primary architecture or post-mortem document from an asset manager or bank describes its agent-harness guardrails; all financial-services evidence is press or vendor-mediated, and no financial-services purpose (for example KYC screening as workflow versus agent) has a published side-by-side comparison. No primary source describes an end-to-end deployment combining Envoy-based routing, KV-cache-aware vLLM scheduling and an agent harness; the placement table is synthesised from component documentation, and the Agent Router documentation did not state whether its rate limiting is token-based or whether it exports OTel GenAI metrics.

Several numbers in this report are weaker than their precision suggests. The official BFCL v4 leaderboard did not render, so open-weight tool-calling standings come from an aggregator that mixes imported and self-reported rows across dates. HarnessTax and the Shandong preamble-token study were available only through secondary reporting. The Terminal-Bench 2.0 paper's own harness-versus-model statement could not be verified beyond an aggregator summary that attributes more effect to model choice, which conflicts with the ICML 2026 workshop paper and the April 2026 compilation; treat the size of the harness effect on that benchmark as unresolved, even though its direction is supported by the controlled SWE-bench factorial. The CLEAR framework's six-variant table has internal inconsistencies and thin task provenance and is cited as a framework, not evidence. Anthropic's 90.2 percent multi-agent gain is on an internal evaluation and LangChain's architecture benchmark reports no numeric scores in text. On standards, the current post-v1.42 GenAI semantic-convention documents in the new repository could not be fetched, the MCP Registry's general-availability status as of November 2026 is unconfirmed, and whether A2A has joined the Agentic AI Foundation is asserted in one blog without a source. On regulation, SR 26-2's text was read directly but trade-press analysis was not retrieved, and Gartner's own glossary definition of an agent could not be fetched. Finally, the phrase "no gate, no action" could not be traced to any primary source; the idea is embodied by the pre-action gate pieces cited and by 12-factor's instruction to break the loop on certain tool calls, but it should not be attributed to a named author.

## Conclusion

The research reframes what VI is building. The product is not a set of agents but a harness that produces them: a loop VI owns, control that lives outside the model, a ledger that records approvals as security objects, a cache discipline that makes a 27B model cheap to run in a long loop, and an evaluation protocol that turns "which build should we use" into a measured answer with a Pareto frontier, a pass^k figure and a calibrated judge behind it. Once the harness is the product, the three-variant offering per purpose stops being a research curiosity and becomes the portfolio's unit of delivery, because every published comparison shows the winner is task-shaped and model-shaped rather than universal, and because the serving configuration of a fine-tuned open-weight model is part of what is being compared. The regulatory position, which leaves generative and agentic AI to the firm's own framework, is an opening rather than a burden: it lets the agent register be designed around autonomy tiers and harness identity from the start, instead of being retrofitted onto a model inventory built for quantitative models.

Two implications go beyond what any single source says. First, the default classification for new ideas should be the lowest agency level that can do the job, and promotion should require evidence that the step count is unpredictable or that tools are mandatory, because the firms and studies that measured it found that most of what is called an agent is a workflow and that the workflow was cheaper and more reliable. Second, VI's planned index will produce something the literature does not have: a record of which variant business teams choose when shown quality, cost, latency and reliability side by side, and whether their choice tracks the measured frontier or departs from it. That record, more than any benchmark, is what will tell the Head of VI whether readily available means readily adopted.

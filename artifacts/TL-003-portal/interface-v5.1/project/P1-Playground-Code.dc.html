Generated from the set-up: prompt advisor-summary-v7, the transcript file, fetch_passage, temperature 0.2, max tokens 800, the prod route.
from relay import Client

client = Client(use_case="UC-0291")                 # Advisor summary
reply = client.generate(
    model="uc-0291:prod",                           # the alias is the model name; the gateway resolves it
    prompt_template="advisor-summary-v7",
    input=open("transcript-2026-11-04.txt").read(),
    tools=["fetch_passage"],
    temperature=0.2, max_tokens=800,
    tags={"env": "pilot", "cost_centre": "RA-4410", "app": "advisor-desktop"},   # required on every call
)
print(reply.text, reply.trace_id)

client.feedback(                                    # what the playground grade sends
    trace_id=reply.trace_id,
    outcome="accepted",                             # accepted, corrected or rejected
    grade=5,
)

What the code carries

Four things every call to a ThinkLatent route needs, and why.
Alias as the model name
model="uc-0291:prod"
The gateway resolves prod to TLM4 Domain-Advice v2 for this project. When the route moves to a new release, the code does not change. Pin a release by name only to reproduce an old result.
Required tags
tags={"env", "cost_centre", "app"}
Cost, usage and quality are attributed by these tags, so the use case's traffic, budget and record stay right. Untagged calls get a warning header from day 14.
Feedback call
client.feedback(trace_id, outcome)
Sends accepted, corrected with the fix, or rejected against the trace. This is how the use case's acceptance and corrections are counted and how fixes reach the regression suite.
Trace id
reply.trace_id
Keep it beside your own logs. Support tickets, replays and disputes start from the trace id; production content behind it stays sealed.

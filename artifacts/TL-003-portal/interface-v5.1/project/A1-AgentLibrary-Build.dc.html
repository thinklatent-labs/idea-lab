Three ways to start

Each path ends with the same things in place: the agent's alias, the required tags, the feedback call, an eval set and an approval template.
1 · New project

Adopt with everything prefilled

Adopt opens Start a project with four things filled in from the agent's record. Change any of them before you submit.

Routing
The agent's prod alias; production on a dedicated endpoint, sandbox and pilot on the shared pool
Eval set
The agent's library suite, with room for 50 of your own cases
Budget
Cost per task times your expected volume, alert at 80%
Approval
The template for the agent's tier and class, approvers named

2 · Your own code

Fork a starter repo

Working code for one agent, cleared for inner-source use, with a named maintainer and a release on the first Tuesday of each month.

Client
Relay client preset: the alias, required tags and feedback call already wired
CI
An eval hook runs 50 smoke cases on every merge; a regression blocks the merge
Deploy
A deploy chart: dedicated endpoint for production, shared pool below it
Guide
Customisation guide for prompts, corpus connectors and refusal wording
3 · An app you already run

Retrofit an existing app

For an app that calls a model directly today. It keeps its code and gains the agent's route, evaluation and approvals.

  1. Register the app's use case, if it has none
  2. Swap the model id for the agent's alias
  3. Add the required tags and the feedback call
  4. Run the eval hook once on a sample of your traffic
  5. Ask for approval with the agent's template
Median effort half a day, across 5 retrofits

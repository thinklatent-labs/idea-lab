1 · A code workspace, beside the chat

The chat narrows · the workspace opens when an agent first needs to keep a file

A workspace is a folder of files that an agent can read, change and run code in, inside ThinkLatent's sandbox at the Enterprise, with no network. It asks before every write, every run and every install. The files are yours to read and download.

2 · What it asks before it does

Three kinds of ask, every time

A run, a write and an install each wait for your yes, with what will happen spelt out. One yes covers one action. There is no "always allow", no "accept all edits" and no full access.

Research helper wants to write a file Change compare_fees.py: 1 line out, 1 line in.
rows = list(csv.DictReader(open(sys.argv[1])))- rows.sort(key=charge)+ rows.sort(key=charge, reverse=True)
Research helper wants to install a package tabulate 0.9, from the Enterprise's own package source. It stays in this workspace only.

Not offered: "accept edits" and "full access", the modes that would let an agent write or run without asking.

4 · The output of a run

What the code printed, and what it wrote

A run shows the command, how long it took, what it printed and which files it made or changed. A run that ends with an error says so in words; nothing is hidden behind a code.

Ran in 0.4 seconds · 11:42 
$ python compare_fees.py sample-funds.csv
Read 3 funds
Wrote fees.md (5 lines)
Made 1 file: fees.md · changed none · removed none
The run ended with an error · 0.3 seconds 
$ python test_compare_fees.py
AssertionError: expected 3 rows, got 4
No file was made or changed. The agent has read the error and will propose a fix, which it asks for like any write.

5 · Installing something

Only from the Enterprise's own package source

The sandbox has no network. A package can come from one place only, the Enterprise's own package source, and each install asks. A package that is not there is not fetched from the internet.

8 · What a workspace can never do

The same for every agent and every person

These hold whatever the code says and whoever allowed it. A yes lets one action run inside the sandbox; it never widens the sandbox.

9 · When something goes wrong

Three more states

Each says what happened and what to do. The chat itself keeps working when the sandbox does not.

The run was stopped after 60 seconds
Runs are stopped at 60 seconds. What it had printed is shown; files it had half written were put back as they were.
The workspace is full
200 MB of 200 MB used. Nothing more can be written until a file is removed.
The code sandbox is not answering
Your files are safe and the chat still works. Runs and writes wait until it is back.

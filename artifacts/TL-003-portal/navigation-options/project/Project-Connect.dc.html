# Call summary · Production
from relay import Relay

relay = Relay()   # signs in as the registered application · nothing secret in the code

answer = relay.chat.completions.create(
    model="advisor-desktop-prod",    # your endpoint · you never name a version
    project="advisor-desktop",       # required
    feature="call-summary",          # required
    session=call_id,                 # one advice call is one session
    user=advisor_ref,                # an id you choose · never a name
    messages=[{"role": "user", "content": transcript}],
)

# afterwards, so the feature is judged on what happened
relay.feedback.create(request=answer.id, thumb="down", reason="missed an action")
relay.outcomes.create(session=call_id, outcome="follow-up booked")
The shape of a call, in the OpenAI style the Relay package follows. The exact field names are still to be confirmed with ThinkLatent AI engineering. In the lower environment two things change: the model's name stands in for the endpoint, and the package is given a key.

What changes under you, and what does not

The endpoint's name staysYou call advisor-desktop-prod whichever version of the model is behind it.
A version changes only by an incrementVersion 3 is due 21 Nov. It reaches your endpoint when you agree to the switch, with your own results already run.
The old version waits 90 daysGoing back needs no change in your application.
A new feature gets a new feature idIt is made when the feature is added to the project. Until then a call using it is refused.

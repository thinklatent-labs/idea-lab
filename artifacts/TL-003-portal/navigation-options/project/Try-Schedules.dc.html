3 · What a run may do with nobody there

The same for every schedule

A run cannot be asked "allow this once", because nobody is there. So a tool that changes something is not available to a schedule at all. A run reads, works things out and writes its answer.

It may

Read with the tools you switched onApproved documents, your files, a connector that only reads Calculate, and run code in the sandboxInside the Enterprise, no network Send up to 2 helpersEach counts as one more request Make an artifact or a fileKept with the run's session for 30 days

It may not

Use a tool that changes somethingSaving, sending, writing to a system: left out of every run Ask you a question and waitIt ends there; the inbox line carries the question Send its result anywhere but your inbox Take in client data, or reach outside the EnterpriseThe same check and the same rule as when you are there

A run stops after 25 steps or 10 minutes, whichever comes first, and says where it got to. Both are sample values that ThinkLatent sets.

6 · A run that failed, or was stopped

Said in the list, in the inbox and in the session

A stopped or failed run says what happened and what to do next. Three failed runs in a row pause the schedule, so it does not keep failing unseen.

9 · How runs count against your limit

The same 60 a day

A run counts as one request on the day it runs, and each helper it sends counts as one more. A run that is due when the day's requests are used is skipped, not saved up, and your inbox says so.

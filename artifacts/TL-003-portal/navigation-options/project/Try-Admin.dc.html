5 · The daily limit, and how it is set

One number for everyone

The limit protects the shared endpoints, which everyone at the Enterprise uses at once. It is never raised for one person. It is counted by the gateway, so it holds however a request arrives.

6 · How long things are kept

And who can read them

A session is a try-out and ends by itself. What you build is kept until you remove it. Nothing is used for training, and the text of a session is kept where only you can read it.

7 · What is checked for client data

Always on · the same for everyone

ThinkLatent's guardrail model reads what is about to go to a model, inside the Enterprise. If it finds a client's details, that message, file or tool result goes no further and is not kept. Made-up people and sample funds pass.

Where it runs
What you sendWhen you press Send, not while you type Each fileWhen it is attached, saved or given to an agent or a folder What a tool or connector brings backBefore the model reads it What memory would keep, and what you saveA memory line, a saved prompt, an agent's instructions
What it looks for
A person's name beside an account or policy number Account, card and national identity numbers by themselves A named person's holdings, balance or transactions A named person's home address, date of birth, phone or own email

A stop does not count against your limit. If the check stops something that is not a client's details, say so with "Why" on the notice: that becomes a request, without the text.

11 · The same page, as ThinkLatent's own people see it

ThinkLatent only · two more columns · still nothing to edit

There is no settings screen. Every value lives in the repository's configuration and changes only by a change that a second person at ThinkLatent reviews; it takes effect with the next release of Try TLM, never live. The review is the record of who changed what, and why.
